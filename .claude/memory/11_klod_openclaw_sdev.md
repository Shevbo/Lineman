# Клод в openclaw на sdev (автономный, на Opus)

Состояние на 2026-10-02. Поставлено по задаче Бори: «элитный openclaw с одним Клодом
на sdev на актуальных версиях, работает как часы, не жрёт токены впустую, ни одной
ошибки в журнале».

## Что где

| | |
|---|---|
| узел | sdev (cursorrpa, 10.66.0.4), Ubuntu 24.04, 10 ядер, 16 ГБ |
| openclaw | **2026.9.7**, две копии: `/opt/node24/lib/node_modules` (её запускает юнит) и `/usr/local/lib/node_modules` (CLI) |
| Node | 24.21 в изолированном `/opt/node24` — системный Node не трогали |
| агент | единственный, `klod-access`, модель `klod-anthropic/claude-opus-4-8` |
| провайдер | `klod-anthropic` → `http://10.66.0.1:9090/proxy/anthropic`, заголовок `X-Agent-Name: klod-access` |
| токен | НЕ в конфиге openclaw: OAuth инжектит Lineman по заголовку |
| плагинов | 2 включено (было 31 из 64) |
| служба | `systemctl --user` → `openclaw-gateway` |

## Главная причина, на которую ушёл день

Запросы openclaw к Anthropic отвергались, и это было НЕ формат тела, НЕ потоковый
режим, НЕ инструменты, НЕ `cache_control`, НЕ `user-agent` — всё это по отдельности
проходило с кодом 200. **Виновата была устаревшая версия openclaw 2026.9.4**: она
формировала запрос так, что Anthropic его не принимал. После обновления до 2026.9.7
всё заработало напрямую, без обходных путей.

Урок на будущее: когда каждая часть запроса проходит, а целое — нет, подозревай
версию клиента, а не поля запроса.

## Обновление openclaw: где грабли

* Пакет живёт в `/opt/node24`, а `npm install -g` ставит в `/usr/local` — обычное
  обновление молча ставит ВТОРУЮ копию, и юнит продолжает работать на старой.
  Обновлять обеими командами:
  `sudo /opt/node24/bin/npm install --prefix /opt/node24 -g --force --allow-scripts=@google/genai,esbuild,koffi,protobufjs,openclaw openclaw@latest`
* Без `--allow-scripts` не ставятся bundled-плагины, потом сыпятся ошибки.
* После обновления база агента требует миграции: gateway падает с `status=78/CONFIG`
  и сам подсказывает `openclaw doctor --fix`. Это штатный шаг, не поломка.

## Конфиг: чего схема не принимает

Проверка строгая, неизвестный ключ роняет gateway в отказ. На этом поймался дважды:
* поля `instructions` у агента НЕТ — личность задаётся файлами в workspace
  (`AGENTS.md`, `SOUL.md`, `USER.md`);
* служебный ключ в корне (я пробовал `_disabled_agents`) не проходит — отключённых
  агентов храню отдельным файлом `~/.openclaw/disabled-agents.json`;
* отключая агента, обязательно перевести на живого `agents.defaults.systemAgent.agentId`
  и `talk.agentId` — иначе конфиг невалиден.

Всегда: `openclaw config validate` ПЕРЕД рестартом, копия конфига рядом.

## Что отключено и почему

`main` и `blogger` (были на lmstudio) вынесены в `disabled-agents.json`; их базы и
workspace на диске целы, возврат — одной правкой. 29 плагинов отключены: каждый
добавляет описания инструментов в КАЖДЫЙ запрос, то есть платные токены за то, чем
Клод не пользуется. `memory-core` тоже отключён — он требовал провайдера эмбеддингов
и писал в журнал ошибку на каждый запрос, а знания федерации Клод берёт из fedrag.

## Замеры после настройки

* 5 запросов подряд — 5 ответов;
* журнал с момента старта: 46 строк, **0 с ошибками или предупреждениями**;
* 5 минут простоя — **0 запросов**, в тишине не тратит ничего;
* одинаковые запросы ловит дедуп Lineman и отдаёт из кэша (5 проб = 635 токенов,
  ни одного обращения к провайдеру).

## Проверить состояние

```bash
ssh sdev 'openclaw --version; openclaw agents list; systemctl --user is-active openclaw-gateway'
ssh sdev 'journalctl --user -u openclaw-gateway --since "$(systemctl --user show openclaw-gateway -p ActiveEnterTimestamp --value)" | grep -ciE "error|warn"'
ssh sdev 'openclaw agent --agent klod-access --session-id proba-$(date +%s) --message "ответь одним словом: ок"'
```

Повторная проба ОДНИМ И ТЕМ ЖЕ текстом попадёт в дедуп Lineman и вернётся из кэша —
это не поломка, а экономия; для честной пробы меняй текст или `--session-id`.
